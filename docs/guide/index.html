Claude Code를 Azure Databricks에 연결하기

노트북의 Claude Code가 Azure Databricks의 Claude 모델을 쓰도록 연결합니다. 실제 Azure에서 따라 한 화면 캡처와 영상으로 정리했습니다.

먼저 구성을 고르세요

A · LiteLLM 없이

직접 연결

💻 노트북Claude Code→☁️ Azure DatabricksAnthropic Messages API

중간 서버 없이 Databricks의 Anthropic 네이티브 API를 바로 호출합니다. 값 3개(URL · Token · Model ID)면 됩니다.

  • 개인 PC에서 빠르게 검증하고 싶을 때
  • 가장 단순한 구성 — 따로 운영할 서버가 없음
  • workspace가 없으면 3분 만에 새로 만드는 단계 포함
⏱ 약 15분🎬 영상 10개🖼 화면 10장
직접 연결 가이드 시작 ▸
B · LiteLLM 경유

게이트웨이 연결

💻 노트북Claude Code→🔀 LiteLLM게이트웨이→☁️ Azure DatabricksFoundation Model API

노트북에는 LiteLLM 주소와 key만 두고, Databricks 토큰은 LiteLLM 서버에만 보관합니다. Claude Code 값 2개만 바꿉니다.

  • 팀·조직이 키·모델·로그를 한곳에서 관리할 때
  • 기존 모델 이름(alias)을 그대로 유지
  • 여러 provider를 한 주소로 통합
  • 이미 쓰는 LiteLLM 서버가 있어도 OK — 기존 서버 연동 방법 포함
⏱ 약 15분🎬 영상 6개🖼 화면 2장
LiteLLM 경유 가이드 시작 ▸
🏢
이미 LiteLLM 서버가 있다면

새로 만들지 않고 기존 서버에 Databricks 모델만 추가합니다. 관리자는 credential과 모델 항목을 넣고, 사용자는 Claude Code 값 두 개만 바꿉니다. Databricks 모델이 이미 등록돼 있다면 사용자는 B 가이드의 6단계부터 시작합니다. → 기존 LiteLLM 연동 방법

두 방식 비교

A · 직접 연결B · LiteLLM 경유
Claude Code ANTHROPIC_BASE_URLDatabricks /serving-endpoints/anthropicLiteLLM URL
Claude Code 토큰Databricks PAT / OAuthLiteLLM key (사용자별 virtual key 권장)
Databricks credential 위치사용자 PC마다LiteLLM 서버에만
모델 이름databricks-claude-*같은 이름을 alias로 유지
이럴 때개인 검증, 가장 단순중앙 인증·예산·로그·여러 provider 통합
✨
처음이라면 A → B 순서로

B 가이드는 A에서 만든 Databricks 접속 정보(URL · Token · Model ID)를 그대로 씁니다.
